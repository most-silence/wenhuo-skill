# 素材卫生：转写、ASR 错误谱、真实数据对账

含音频/视频素材的蒸馏，错误大头不在方法论，在**转写层**。本文件规定清洗红线与对账程序。

## 1. 铁律：转写稿不润色

表达 DNA 藏在口语里。犹豫、自我修正、用词偏好都是风格证据；润色一次，销毁一次。

- **禁止**：AI 总结、AI 改写、删口语、合并重复、把口语补成书面语
- **允许**：去纯噪音（背景音乐、广告口播可标注后保留原文）；繁简转换；同音错字修正（走 §2 词表，逐条留痕）

## 2. ASR 错误谱

转写错字的分布不是随机的，按五类建**同音词表**（`{对象}/tools/check_transcript.py` 类工具，每条修正留对照记录）：

| 类别 | 例（金融域） | 例（通用） |
|---|---|---|
| 术语同音 | 量能→亮能、筑底→注底 | 概念被听成常用词 |
| 数字互混 | **双向**：2↔3、6↔8、0 吞音 | 编号/日期错位 |
| 专名 | 人名/代号听碎 | 作品名、机构名 |
| 口头禅误合 | 「谨记」→警惧、「另一档」→另名 | 固定句式粘连 |
| 断句 | 时间戳插入致语句切碎 | 标点误置 |

**关键认知：数字错误是双向的。** 你观察到「A 与 B 算术不合」，无法由此判定错的是 A——B 也可能错，甚至两个都错。**词表内部互证只能缩小范围，最终裁决权在外部数据（§3）。**

## 3. 真实数据对账（本框架独有硬闸）

对象说出的可验证数字（点位、日期、比分、引用），入库前必须有「当日实际值」列。

流程：

1. 拉外部数据源覆盖素材时段（行情/赛果/史料按领域选；本项目工具链：`fetch_market.py` 多源互备）
2. 逐条对账：声称值 vs 实际区间 → 判定「区间内/区间外/已触发/未满足/无法验证」
3. 对不上的先怀疑 ASR 而不是对象说错——**双向核对，谁错由数据说了算**
4. 绝对金额类数据拿不到时（源限流），退化为方向性验证（放量/缩量），并显式标注「无法逐日验证」——**标注缺口，不许假装验过**

真实事故档案：口播「2860」被 ASR 听成「3860」，另一处「2800」听成「3800」——两处都错时，任何句内算术（3860−3850=10 ✓）都能「自洽」出**相反**的结论。只有真实行情（全段最高 3270，从未接近 3800）能裁决。

## 4. 分批到达与长尾素材

- 音频获取受平台分页限制时：元数据收割（浏览器滚动/存档页）与音频下载分离，先收全清单再慢慢下载
- 每批素材到达 → 走增量协议，**不许攒一批大改**
- 采样纪律：跨阶段样本 > 连续样本。只采单一行情段/单一主题的素材，蒸馏出的是「他在顺风期的样子」

## 5. 清洗管线（可复用工具形态）

```
原始音频 → ASR（本地 medium 级，beam_size=1）→ 繁简归一 →
同音词表修正（留痕）→ 时间戳保留 → 规则抽取（引文纪律：一条结论一行原话）→
ASR 存疑清单（每条带「判断依据」列，供数据对账复核）
```

引文纪律：抽取阶段每条规则必须带**原话字段**，且原话只许来自转写稿逐字摘录。后续所有修正（对账、清洗）都只动标注，不动原话。
