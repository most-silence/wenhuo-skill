# 玟火 · WENHUO

**人设蒸馏框架 / Persona Distillation Framework**

> 文火慢蒸，去芜存玟。 *Slow fire, true essence.*

把一个人的**公开素材**（书、播客、视频、文章）蒸馏成一套可被 AI 调用的**认知操作系统**——
不是语录合集，是「遇到新问题，他会怎么想、怎么判断、怎么说话」的可执行模型。

本框架诞生于「眼哥」项目（一位股票博主）的实战，四条来源流水线 + 三次事故教训。
每个环节都有真实事故对应，不是纸面方法论。

---

## 这是什么 / 不是什么

| 是 | 不是 |
|---|---|
| 把「怎么想」蒸成可调用 Skill | 把「说了什么」整理成摘要 |
| 每条结论带引文、每条数字过真实数据对账 | 凭印象转述、替对象「完善」逻辑 |
| 分数只升不降的棘轮进化 | 每次重写赌运气 |
| 保留矛盾（两个说法都真，就都留着） | 和稀泥式的「综合」 |
| 明确的诚实边界（他不懂什么） | 全知人设 |

## 怎么用

**给 Agent（主用法）**：把本目录整体放进你的 skills 目录（或让 Agent 直接读
[`SKILL.md`](SKILL.md)），说「蒸馏 XX」/「更新 XX 的 skill」即可。
`SKILL.md` 是运行手册：六个 Phase、三道门、五条铁律，references/ 按需加载。

**给人**：先读本页 → 按 [`SKILL.md`](SKILL.md) 的 Phase 0 立项 → 每个 Phase 结束过 🔴 门再走下一步。

**换领域**：SKILL.md 的 8 维是通用的；高危/强验证领域加领域包（已内置
[`domain-packs/investing.md`](domain-packs/investing.md)：12 维 + 行情对账端点 + 合规红线）。

**复用脚本**（`tools/`，均为眼哥项目实战版，换对象只改文件头部的表）：

| 脚本 | 用途 | 需替换的对象常量 |
|---|---|---|
| `parse_podcast.py` + `download_podcast.py` | 小宇宙页面解析与音频下载 | 播客 PID |
| `harvest_by_cdp.py` | 驱动本机浏览器滚动收割全量剧集清单 | PID / 输出路径 |
| `transcribe.py` | faster-whisper 本地批量转写 | DOMAIN_PROMPT |
| `check_transcript.py` | 同音词表清洗（留痕） | HOMOPHONE 表 |

| `check_names.py` | 发布前撞名体检（GitHub/PyPI/npm） | 候选表 |

## 架构总览

> **Agent 的执行入口是 [SKILL.md](SKILL.md)**（含 frontmatter、门判据、完成标准）；本节是给人看的浓缩版。

```
第 0 步  选档           快速 / 标准 / 深度 / 滚动增量（素材分批到达时用）
   ↓
第 1 步  多路采集        按维度并行，每条信息标来源与可信度，落盘即断点
   ↓       🔴 门：来源数 / 关键发现 / 矛盾点，人工确认
第 2 步  框架提炼        三重验证 → 心智模型 + 启发式 + DNA + 反模式 + 诚实边界
   ↓       🔴 门：模型方向对不对，在这里拦
第 3 步  Skill 构建      填 SKILL.md（人设层），或编译成能力卡（书上层）
   ↓
第 4 步  质量验证        Q1–Q11 + 真实数据校验 + paired 盲评（新评委、多数决）
   ↓       🔴 门：本次 ≥ 上次，否则回滚
第 5 步  注册与增量      快照 → 版本三处同步 → 进入 9 步增量协议
```

### 素材线隔离（多源对象必开）

| 规则 | 内容 |
|---|---|
| 1 | 每条线一个目录：`sources/0N-线名/`，产出物各线一份，**永不合并成一份混源文档** |
| 2 | 任何文档的每个结论，来源行号必须落在本线素材内 |
| 3 | 跨线引用必须显式标注「桥接」，且只在比对文档里出现 |
| 4 | 发布前跑一致性检查：grep 各线术语的越线命中数，期望 0（边界声明除外） |

为什么：三线混在一起时，「他说过 X」无法归因于哪部素材，回滚和验证都失效。

### 三重验证（观点升格门）

| 关 | 判定 | 不过 |
|---|---|---|
| **V1 跨域复现** | ≥2 个不同场景出现过 | 降级为启发式 |
| **V2 生成力** | 能推断他对新问题的立场 | 降级或丢弃 |
| **V3 排他性** | 不是所有聪明人都这么想 | **直接丢弃** |

### 盲评方法

- 评委是**独立子 Agent，每轮换新，不复用**（LLM 自评准确率仅 46.4%）
- **paired 三向同题对比**（旧版 / 上次新版 / 本次新版），N=3 奇数多数决
- 必须覆盖三类非主路径题各 ≥3 道：闲聊情绪 / 多轮追问 / 极端场景
- **棘轮铁律：分数只升不降，低于基线就回滚，绝不「先合进去再说」**

### 增量协议（9 步，不许裸改）

```
入口 → diff → 影响分析 → 快照 → 合并（旧结论保留+新证据标注）
     → 纠错层 → 盲评 → 版本三处同步 → 登记 + 索引健康检查
```

## 血泪规约（事故换来的，优先级高于一切）

1. **「他说过 X」要一条引文；「ASR 听错了 X」要真实世界数据裁决。**
   句内算术自洽 ≠ 事实正确——双变量错误下，单条线索无法定案。
   抽取的原话数字必须配「实际值」列，对不上就回炉。
2. **阴性断言的举证责任重于阳性。**
   说「他没讲过 X」之前：检索四类词（术语/大白话/近义词/场景词）+ 全文分段读完。
   拿不出检索记录，就不许写「未涉及」。
3. **素材长度 ≠ 素材价值。** 越长的口播越可能藏具体数字，「看起来像重复」不许跳。
4. **冲突不抹平。** 两个说法都有原文，就都保留并互相引用；裁决需要新素材，不需要立场。
5. **数字表格先验算再落笔。** 看到 A+B+C 并列，先问是否同一层级；凡比例/倍数必手算一遍。
6. **专有名词优先核对。** 转写错字先建同音词表；ASR 数字错误是双向的（2↔3、6↔8 都可能）。

## 合规红线（高危领域必抄）

| 红线 | 处理 |
|---|---|
| 不替对象编造言论/战绩 | 查不到出处不用；Q1 溯源 |
| 不把通用道理包装成独特见解 | V3 排他性直接丢弃 |
| 不生成可执行的高危指令（买卖/用药/投资参数） | 只输出「他会怎么看这个问题」 |

## 命名

**玟火**（wén huǒ）。火是**文火**——低热慢工，分批到达、逐条对账、每轮盲评、只进不退；
炼过之后剩下的，是**玟**。

玟字有两支古训，都落在本框架的隐喻上：

| 出处 | 训释 | 对应什么 |
|---|---|---|
| 《康熙字典》玉部引《集韵》：玟「与珉同。**瓀玟，石次玉**。《礼·玉藻》：士佩瓀玟而缊组绶」 | 石之次玉者——粗石经琢磨，得配玉之质 | 去芜存菁：素材是石，火候炼出玉 |
| Unicode Unihan `U+739F`：**streaks in jade**（gem） | 玉的纹理 | 蒸馏的不是结论是纹理：「决策链 > 结论」 |

读音 wén（又 mín），从玉文声——中文名「玟火」与拼音英文名 `wenhuo` 同token，
搜一个必见另一个。曾用名「文火」（v0.11），v0.12 起定为「玟火」，读音不变。

仓库名：**`wenhuo-skill`** → https://github.com/most-silence/wenhuo-skill （v0.12 已发布）。
撞名体检（2026-10-26）：GitHub 同名仓库 `wenhuo` 仅 2 个 0–1★ 个人练手；
PyPI / npm 均空闲。
