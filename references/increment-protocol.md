# 增量修改协议 · 九步

已有 `SKILL.md` 之后，每次更新都走这九步。**禁止裸改。**
核心原则：增量是「带纠错层的合并」，不是重写。

## 前置：读基线

- [ ] 确认这是「更新」不是「新建」；读现有版本号与「调研截止」时间
- [ ] 从 `outputs/` 找到上一版盲评作答——这是棘轮基线，没有它就不许开评
- [ ] 判断新材料属于哪些维度，列受影响章节

## 1. diff

三清单：**新增**（全新信息）/ **修改**（与现有冲突需更正）/ **删除**（已过时或被本人推翻）。

## 2. 影响分析

列出依赖这些内容的章节、模型、启发式、索引条目。一处数字变，先查所有引用它的表格和算例（Q11）。

## 3. 快照

改前全量备份到 `snapshots/<timestamp>/`。回滚只能指向这里。

## 4. 合并

新材料归入对应段；**旧结论保留并标注「原结论 + 新证据」**。仅在明确矛盾时修改，且必须记录「为什么改」。冲突不抹平：两个说法都有原文，就都保留。

## 5. 纠错层

用户说「他不会这样，他会 xxx」→ 写入 Correction 段，立即生效，优先级高于一切旧表述。这是人针对 AI 的最后一道保险。

## 6. 盲评

paired 三向（旧版 / 上次新版 / 本次新版）+ N=3 独立评委多数决，规则见 [eval-protocol.md](eval-protocol.md)。

## 7. 棘轮判定

本次 ≥ 上次 → keep；否则 **revert 到快照**。禁止「先合进去再说」。

## 8. 版本三处同步

SKILL.md / README / PIPELINE_STATE（或 CHANGELOG）版本号一致；当日多次改动当日补记。

## 9. 登记

更新调研时间与「最新动态」；跑索引健康检查（引用路径/行号失效数 = 0）。
